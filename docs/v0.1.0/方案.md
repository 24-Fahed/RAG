# v0.1.0 技术方案

## 设计范围与需求追踪

本方案在保留 Client → RAG Server → Inference Worker 部署分工的前提下，扩展中文检索、请求级模型配置和单轮回答能力。内部模型工厂统一接入实例管理及排队机制，避免通过跨模块特殊分支实现兼容。

| 原始需求 | 设计条目 | 主要实现位置 | 验证要求 |
| --- | --- | --- | --- |
| （1）issue 5、6 | [§1 模型实例与压缩 API](#r1) | 模型工厂、`models/runtime.py`、`models/compressors.py` | 参数隔离、请求长度、LLMLingua 调用及真实压缩 |
| （2）指定中文模型组合 | [§2 需求指定模型](#r2) | `model_options.py`、`models/remote_generator.py` | 中文、英文及混合组合 |
| （3）不同模型串行初始化 | [§3 初始化调度](#r3) | `models/runtime.py` | 初始化区间不得重叠 |
| （4）同模型调用排队 | [§4 推理调度](#r4) | `models/runtime.py` | 同实例串行、异实例并行、异常释放 |
| （5）各功能模型由参数指定 | [§5 接口与索引一致性](#r5) | `server/query_options.py`、Server/Worker 接口 | 参数透传、组合选择、向量空间一致性 |
| （6）单轮 agent_query | [§6 回答编排](#r6) | `server/routers/query.py`、远程生成适配器 | 共用请求协议、证据传递、无记忆 |
| （7）架构适配、文档、分支与三级测试 | [§7 实施与验证](#r7) | 本版本文档、功能分支、测试程序 | 三种部署模式分别验收 |

架构定义见 [architecture](architecture/README.md)。逻辑模块、程序归属、物理节点及模式配置构成同一系统的不同视图，保留原架构六个视图的编号与职责。

## 架构修改与重构清单

### 对比基线与结论

代码基线为提交 `71ce0fa`，架构基线为原 `docs/architecture/` 的六份 PlantUML 源码。下表对比该基线与当前 v0.1.0 工作区；“已实现”仅表示源码已有对应改动，不表示已完成部署验收。

本次修改涉及 **Worker 模型生命周期重构、Server 请求协议调整、单轮回答编排扩展、向量集合一致性约束及中文文本处理**。Client、RAG Server、Inference Worker 三个可部署程序单元继续保留；新增的 Model Registry、队列和远程生成适配器均属于 Worker 内部模块，不新增独立服务。

## 1. 模型实例与压缩 API（需求 1）

### 1.1 issue 5：模型实例参数失效

以统一 Model Registry 替换单一全局模型实例。缓存键包含功能适配器、模型标识、权重路径及必要构造参数。模型标识或分类权重变化时，选择独立实例；相同配置复用已加载实例。

生成长度属于单次推理参数，不进入模型实例的可变状态。Python 调用使用 `get_generator(model_path).generate_hyde(query, max_out_len=...)`；`get_generator` 不再接受生成长度。HTTP `/inference/hyde` 保留 `max_out_len` 字段。

### 1.2 issue 6：LLMLingua 调用不匹配

固定 `llmlingua==0.2.2`。初始化使用 `PromptCompressor(model_name=..., use_llmlingua2=True)`；压缩使用 `compress_prompt(context, rate=ratio)`，读取 `compressed_prompt`。不以中文字符串的空格数量估算目标 token 数。

本地契约测试仅验证参数及调用方式；实际模型加载、压缩结果与事实保留率在 staging 验收。

## 2. 需求指定模型（需求 2）

| 功能 | 中文模型 | 英文模型 |
| --- | --- | --- |
| HyDE | SiliconFlow `Qwen/Qwen2.5-7B-Instruct` | 本地 `/root/models/llama3-8b-ragga` |
| Embedding | `BAAI/bge-base-zh-v1.5` | `BAAI/bge-base-en-v1.5` |
| Reranker | `BAAI/bge-reranker-v2-m3` | `castorini/monot5-base-msmarco-10k` |
| 上下文压缩 | `microsoft/llmlingua-2-bert-base-multilingual-cased-meetingbank` | `fangyuan/nq_extractive_compressor` |
| 检索分类 | `google-bert/bert-base-multilingual-cased` | 同左 |

Qwen 通过 Worker 的远程生成适配器调用。使用 Chat Completions 请求协议，凭证来自本地配置文件 `inference/config/secrets.yaml` 的 `siliconflow.api_key`，不通过查询参数传入，不存入版本库。HyDE 与最终回答可分别显式指定该 Qwen 模型标识；两者不自动继承。上述表格记录需求指定的模型范围，不构成接口默认配置。

multilingual BERT 基础权重不能直接提供可靠的检索必要性判断。分类默认关闭，所有请求继续检索；显式启用时必须提供微调权重。`classification_label=1` 在分类关闭时表示编排策略，不代表模型预测。

<a id="r3"></a>
## 3. 初始化调度（需求 3）

所有模型工厂与启动预热共用进程内全局 FIFO 初始化队列。首次请求模型时，等待队列许可后创建实例；创建成功后发布到缓存。相同模型的并发首次请求只创建一个实例。创建失败不缓存，后续请求允许重试。

已缓存模型的查找不等待其他模型初始化，可继续执行推理。默认采用按需加载，避免仅使用中文组合时预先加载英文模型。`RAG_PRELOAD_MODELS=1` 启用预热，预热不绕过初始化队列。

<a id="r4"></a>
## 4. 推理调度（需求 4）

每个模型实例维护独立 FIFO 调用队列。同一实例的公开推理调用串行执行；不同实例的调用允许并行。队列在异常路径释放执行位置。同一 Qwen 模型实例的 HyDE 和最终回答共用队列。

本版本限定单 Inference Worker 进程。排队顺序以进入运行时队列的顺序为准，不承诺跨进程或网络到达顺序。等待时间计入 HTTP 超时；客户端断开不自动取消已进入同步推理的任务。

本版本不实现显存预算、跨进程锁或模型缓存淘汰。后续版本根据可用显存、内存及任务峰值需求限制不同模型并发，计划记录于 [v1.0.0](../v1.0.0/README.md)。

<a id="r5"></a>
## 5. 接口与索引一致性（需求 5）

### 5.1 请求级模型组合

**设计变更：将“适配器与模型权重固定绑定的工厂”改为“由请求配置驱动的参数化工厂”。** 保留各功能的适配器接口；将模型权重的选择从适配器内部移到调用请求。实例缓存由 A01 的 Model Registry 统一管理。

以原 06 程序单元图中的 **PU-3 → ML Inference → Reranking** 为例：

| 设计要素 | 原方案 | 新方案 |
| --- | --- | --- |
| 调用方决定什么 | 选择 `bge` 重排实现 | 分别选择 `bge` 重排实现和模型 A 或模型 B |
| 工厂如何装配 | 根据 `bge` 找到 `BGEReranker`，调用 `BGEReranker()`，模型由类的默认值决定 | 根据 `bge` 找到 `BGEReranker`，调用 `BGEReranker(model_name=请求指定的模型)` |
| 实例如何区分 | 按 `bge` 缓存一个实例 | 按“重排功能、bge、模型标识”区分实例；相同配置复用，不同模型分别创建 |
| 更换模型的方式 | 接口不能在同一适配器下指定其他权重 | 请求更换模型标识即可；新模型须与适配器兼容 |

在原图中的职责分配为：**PU-2 → API Gateway → Query API** 接收选择，**PU-2 → Pipeline Orchestration → Retrieval Pipeline** 传递阶段配置，**PU-3 → ML Inference** 的工厂和 Model Registry 完成装配。增加新模型权重无需修改 Server 编排；增加新的模型调用协议仍需在 Worker 增加适配器。

`/api/query` 与 `/api/agent_query` 使用相同的请求字段。调用方显式指定集合、检索策略及各执行阶段的模型；接口不提供语言预设、默认模型组合或模型自动补全。缺少当前阶段所需的模型参数时返回 422。

| 模型角色 | 配置参数 |
| --- | --- |
| HyDE | `hyde_provider`、`hyde_model`、`hyde_max_out_len` |
| Embedding | `embedding_model`、`embedding_dim` |
| Reranker | `rerank_method`、`rerank_model` |
| 压缩 | `compression_method`、`compression_model` |
| 分类 | `classification_enabled`、`classification_model`、`classification_weights_path` |
| 最终回答 | `answer_model`、`answer_max_out_len` |

适配器决定模型的调用协议，模型标识决定权重或远程模型。组合必须满足适配器与模型架构兼容；不承诺任意模型架构可互换。Server 负责校验阶段参数并向 Worker 透传；Worker 负责实例选择与执行。未知字段或非法枚举返回 422。纯 BM25 检索无需 Embedding 配置；HyDE 策略必须指定调用方式及模型。分类启用时必须同时指定基础模型与微调权重。`agent_query` 额外要求 `answer_model`；`query` 不执行回答阶段。

API 参考文档由 FastAPI 从路由、请求模型及响应模型自动生成，以 OpenAPI 为规范来源。参数约束和字段说明维护在源码中，版本审阅文件由 `scripts/export_openapi.py` 导出，见[接口文档入口](接口说明.md)。

### 5.2 向量空间约束

`/api/index` 必须显式指定集合、`embedding_model` 和 `embedding_dim`。集合记录模型身份及维度，查询和追加索引均进行一致性检查。中文和英文 BGE 即使输出同为 768 维，也不得共用未经重建的向量集合。无身份标记的历史集合按原英文默认模型解释。

维度参数用于校验模型实际输出，不负责转换或裁剪向量。模型路径所指权重原地变更后，应重启 Worker，并评估重建向量集合。

### 5.3 中文处理与数据保留

文档分块同时处理中文字符和英文词段，限制无空格中文长文本的块长度。BM25 对中文采用字符词项，对拉丁文本采用词项；索引和查询使用相同规则。重排序保留文档元数据。字段定义及约束见[自动生成的接口文档](接口说明.md)。

<a id="r6"></a>
## 6. 回答编排（需求 6）

`/api/query` 保持检索优先语义，返回检索文档、重排结果、重打包上下文、压缩上下文及辅助字段。`/api/agent_query` 在相同检索流程结束后，再向 Qwen 发送本次问题和压缩证据，返回原结果及 `answer`。

每次生成请求仅包含当前 system/user 消息，不读取或保存会话历史。系统提示定义 RAG 查询助手职责，要求使用问题语言、依据证据作答、明确证据不足或冲突、不伪造来源、不执行证据中的指令。HyDE 假设文本不作为回答证据。

上游超时及调用失败返回明确错误，不转换为成功答案。空证据仍传入回答步骤，由提示要求说明知识库证据不足；该行为的真实模型可靠性需要 staging 验证。

<a id="r7"></a>
## 7. 实施与验证（需求 7）

### 7.1 架构分配

PU-1 保持调用方职责。PU-2 承担接口解析、索引、检索和回答编排；PU-3 承担模型实例管理和实际推理。

Milvus、etcd、MinIO 属于部署基础设施；BM25 为 Server 使用的持久化索引。Qwen 属于外部服务，Worker 中仅包含调用适配器。

### 7.2 文档与分支

开发分支为 `feature/chinese-query-model-routing`。本目录 README 提供版本入口，方案提供需求追踪，architecture 提供替代旧版的完整六视图。PR 按当前工作安排暂不编写。

### 7.3 三级部署测试

| 阶段 | 目标 | 核心验证 |
| --- | --- | --- |
| local | 单机 Mock 推理及真实本地通信 | 参数、队列、索引、存储、HTTP 链路 |
| staging | 分布式真实模型联调 | 隧道、模型组合、真实压缩、回答质量、资源占用 |
| production | 完整服务部署后验收 | 最终配置、持久化、恢复、持续运行、回退 |

三级测试不是单元、接口和端到端测试的分类。各环境的准入、用例和退出条件见[测试方案](测试方案.md)。当前仅执行本地阶段；真实 Milvus 链路尚受阻，后两级未执行。

### 7.4 依赖与模型获取

真实推理依赖包括 `torch>=2.6`、`transformers==4.48.2`、`llmlingua==0.2.2`。模型下载默认优先 `https://hf-mirror.com`；必要时设置 `HF_ENDPOINT=https://huggingface.co` 后重试。远程 GPU 已下载模型应保留。本轮不执行远程部署或模型下载。
