# v0.1.0 部署阶段测试方案

## 1. 阶段定义

本轮以用户最终确认的范围为准：不再执行本地测试；不测试旧版回退、新旧版本对照、回答语言或指令干扰；分类模型测试暂缓。持续运行按用户指示提前停止，记录实际时长，不以跑满 30 分钟作为退出条件。

三级测试依次为 local 本地测试、staging 线上联调、production 完整服务部署后测试，与本版本三张模式部署图一一对应。单元、接口、端到端是测试组织方式，不代表部署阶段。

| 阶段 | 架构基线 | 环境范围 | 进入条件 |
| --- | --- | --- | --- |
| local | [本地部署](architecture/08_physical_architecture_local.puml) | 单机 Client、Server、Mock Worker、Milvus、BM25 | 代码可启动，测试资源隔离 |
| staging | [联调部署](architecture/09_physical_architecture_staging.puml) | 公网 Server、GPU Worker、SSH 隧道、真实模型与 Qwen | local 完整链路通过；远程工作恢复 |
| production | [生产部署](architecture/10_physical_architecture_production.puml) | 最终配置下的完整服务 | staging 验收通过；版本、配置与性能基线冻结 |

测试必须使用独立集合和可识别的资源名称，不得覆盖现有业务集合或删除已有模型。报告必须标明替身边界、实际拓扑、环境版本和未执行项。

## 2. local 本地测试

| 用例组 | 验证内容 | 对应需求 |
| --- | --- | --- |
| 模型实例 | embedding 模型/维度、分类权重、生成模型切换；相同配置复用 | 1、5 |
| 初始化队列 | 不同加载区间不重叠；同模型首次加载去重；失败重试 | 3 |
| 调用队列 | 同实例串行、异实例并行、异常释放、请求长度隔离 | 1、4 |
| API 契约 | LLMLingua-2 初始化及压缩参数；Qwen 请求格式与异常响应 | 1、2、6 |
| 查询协议 | 各阶段模型显式指定、中英文混用、阶段必填校验、非法参数、元数据保留 | 2、5 |
| 编排 | 上传索引→检索→压缩→模拟回答；分类跳过及空证据 | 5、6 |
| 物理链路 | 独立进程 HTTP、真实 Milvus 读写、BM25 保存重载、Server 重启 | 7 |

代码回归允许替换模型及存储边界；完整物理链路必须使用真实 Milvus，模型保持 Mock。局部 BM25 链路不能替代向量检索和上传索引验收。

### 执行方式

```bash
python -m venv /tmp/rag-query-venv
/tmp/rag-query-venv/bin/pip install -r tests/requirements-local.txt
/tmp/rag-query-venv/bin/python -m pytest -q
/tmp/rag-query-venv/bin/python tests/prepare_local_storage.py
docker compose -p rag-query-local -f /tmp/rag-query-compose.yaml up -d
# 存储服务健康后执行完整物理链路
/tmp/rag-query-venv/bin/python tests/local_deployment.py
# 仅清理本次测试栈
docker compose -p rag-query-local -f /tmp/rag-query-compose.yaml down -v
```

局部链路命令：

```bash
/tmp/rag-query-venv/bin/python tests/local_deployment.py \
  --bm25-only --report /tmp/rag-local-http-report.json
```

退出条件：代码断言及完整物理链路全部通过，无意外模型下载或外部 Qwen 调用。缺失的基础设施验证须保持未验收状态。

## 3. staging 线上联调

### 3.1 模型与策略矩阵

| 组合 | Embedding | HyDE | Reranker | 压缩 |
| --- | --- | --- | --- | --- |
| 中文 | BGE-zh | Qwen | BGE v2-m3 | LLMLingua-2 |
| 英文 | BGE-en | 本地 LLaMA | MonoT5 | Recomp extractive |
| 混合 A | BGE-zh | Qwen | MonoT5 | LLMLingua-2 |
| 混合 B | BGE-en | Qwen | BGE v2-m3 | Recomp extractive |

各组合分别验证 `original`、`hyde`、`hybrid`、`hyde_with_hybrid`、`bm25`，覆盖 query 与 agent_query。核对实际模型身份，不仅检查 HTTP 状态。提供分类微调权重后，增加 label 0/1 及权重切换用例；未取得权重时保留待验收项。

### 3.2 检索与回答质量

每种语言建立 20 个有明确证据的问题、5 个无答案问题、3 个冲突案例；保存目标文档 ID、关键事实及期望回答约束。统计 Recall@10、重排命中、压缩事实保留、回答依据性及无证据表达。混合组合不预设质量与原生组合相同。

首次联调建立质量和延迟基线，审核后冻结阈值，不得通过事后修改阈值掩盖退化。编造来源、错误模型复用和丢失关键证据作为缺陷处理。

### 3.3 并发与故障

- 同时冷启动多个模型，记录初始化开始/结束时间，确认不重叠。
- 同一实例并发提交 5 个请求，核对推理区间及请求参数；Qwen HyDE/answer 验证共享队列。
- 不同模型并发，记录队列等待、推理耗时及峰值显存/内存；OOM 作为失败，不能以设备标称容量替代测量。
- 在隔离环境注入隧道断连、模型加载失败、Qwen 超时和无效凭证；验证错误传播及恢复后可再次调用。

退出条件：功能矩阵、真实 LLMLingua/Qwen、并发约束与恢复用例通过；质量缺陷闭环；保留模型 revision、依赖版本、日志和资源采样。不得记录密钥。

## 4. production 完整部署后测试

| 用例组 | 验证内容 |
| --- | --- |
| 完整入口 | 从最终客户端地址执行中文、英文、混用的独立冒烟集合 |
| 配置 | 单 Worker、无 reload、最终参数、持久隧道及凭证来源；核对实际日志与访问控制 |
| 持久化与恢复 | 维护窗口分别重启 Worker、Server、隧道和存储，验证自动恢复及索引保留 |
| 持续运行 | 三个并发查询持续运行，记录成功率、p50/p95 和资源采样；实际运行约 18 分 53 秒后按用户要求停止 |

退出条件：最终配置下全部用例通过；无 OOM、错误模型复用或持续增长的资源占用；记录实测性能；本轮没有预先确认的性能阈值，不作阈值达标声明。production 不因物理拓扑与 staging 相同而免测。
