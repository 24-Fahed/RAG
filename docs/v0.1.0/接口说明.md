# OpenAPI 接口文档

接口定义由 FastAPI 路由及 Pydantic 模型生成，规范文件为 [api/openapi.json](api/openapi.json)。

## VS Code 阅读与校验

使用已安装的 **OpenAPI (Swagger) Editor** 扩展（`42Crunch.vscode-openapi`）。工作区已记录扩展推荐。

1. 在编辑器中打开 `api/openapi.json`。
2. 按 `Ctrl+Shift+P`，执行 `OpenAPI: show preview using Swagger UI`；也可执行 `OpenAPI: show preview using ReDoc`。编辑器右上角的预览按钮默认使用 Swagger UI。
3. 使用 OpenAPI 大纲定位接口、请求和响应；使用 Problems 面板查看规范诊断。

上述本地编辑与预览功能不需要启动 RAG 服务。无需注册平台账号或执行云端审计。

## 更新规范

在仓库根目录、已安装 Server 依赖的 Python 环境中执行：

```bash
python scripts/export_openapi.py
```

规范从源码导出，不手工修改 JSON。导出不启动服务、不加载模型、不执行业务测试。

## 运行中服务

运行中的 Server 同时提供 `/openapi.json`、`/docs` 和 `/redoc`。本地 Server 地址为 `http://127.0.0.1:8001`。IDE 预览用于审核规范；实际服务调试使用运行中 Server 的 `/docs`。

## Bearer Token 鉴权

`POST /api/index`、`POST /api/query`、`POST /api/agent_query` 和 `GET /health` 均要求：

```http
Authorization: Bearer <access_token>
```

Token 为 RS256 签名的 JWT，校验签名、有效期、签发者 `rag-server-cli`、受众 `rag-server-api` 及 `rag:api` 权限。缺失或无效 Token 返回 401，权限不足返回 403，服务端密钥配置不可用返回 503。没有在线匿名领 Token 的接口。

Swagger UI 的 **Authorize** 输入框填 Token 本身，不加 `Bearer` 前缀。`/docs`、`/redoc` 和 `/openapi.json` 保留公开访问，业务接口鉴权不因此绕过。

### 密钥和 Token 管理

密钥文件由管理员生成；命令拒绝覆盖已有文件：

```bash
python -m server.auth init-keys --directory /secure/rag-auth
```

Server 通过 `RAG_AUTH_PUBLIC_KEY_FILE` 指定验证公钥的文件路径；签发命令通过 `RAG_AUTH_PRIVATE_KEY_FILE` 指定私钥路径。环境配置中只有路径，密钥内容保存在 PEM 文件中。现有服务器继续使用 `/run/rag-auth` 挂载的文件，不重新生成密钥。

签发一小时有效期的访问 Token：

```bash
python -m server.auth generate-token --subject client --expires-in 3600
```

该命令向标准输出写 Token，调用方应保存到受限文件。CLI 客户端使用 `--token-file /path/to/access.token`（放在 `query` 或 `index` 子命令之前）；Token 仅进入 Authorization 请求头，不进入查询 JSON 或模型参数。

服务器验证结果：[18 项鉴权检查](test-results/bearer-auth.json)。源码 `server/auth.py`、`server/main.py` 与服务器当前运行版本哈希一致；OpenAPI 从同一 FastAPI 应用生成。
